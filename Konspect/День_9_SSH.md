<span style="--tn-background:#e64d4d;background-color:#e64d4d;">SSH(Secure Shell)</span> \- протокол для зашифрованного подключения к удаленной машине. Доступ через его терминал. Главный способ работы с серверами. Порт по умолчанию 22

1.  Команды для подключения
    
    1.  ssh пользователь@адрес  
        ssh velensis@192.X.X.X       # пример

brute force - перебор паролей

На серверах во избежание brute force, вместо паролей <span style="--tn-background:#e64d4d;background-color:#e64d4d;">на сервера заходят по парам ключей</span>

2.  Вместо пароля создается пара ключей, два связных файла:
    1.  Приватный ключ(private key): хранится только у администратора на компьтере. Никому и никуда не передается. Им администратор доказывает что это он.
    2.  Публичный ключ(Public key) - Ключ который хранится на сервере. Его можно отдавать кому угодно

Устроено все так: По публичному ключу нельзя вычислить приватный. А при входе сервер проверяет, есть ли у тебя приватный ключ, не получая его самого, приватный ключ никогда никуда не передается.

3.  Упрощенная схема работы ключей:
    
    1.  1\. ты     ──▶ сервер:  «хочу войти как velensis»  
        2\. сервер:            ищет у себя публичные ключи velensis  
        3\. сервер ──▶ ты:     случайное число, «задачка», каждый раз новая  
        4\. ты:                подписываешь задачку ПРИВАТНЫМ ключом  
        5\. ты     ──▶ сервер:  подпись (не ключ!)  
        6\. сервер:            проверяет подпись ПУБЛИЧНЫМ ключом  
                             ✅ сошлось: пускает  
                             ❌ не сошлось: отказ
    2.  <span style="--tn-background:#e64d4d;background-color:#e64d4d;">Цифровая подпись</span> - цисло вычисляемое из “Задачки” и приветного ключа. Публичным ключом можно проверить, что подпись сделана парным приватным ключом, но самому такую подпись сделать нельзя.
        1.  Почему это надежно
            1.  Задчка каждый раз новая и случайная, поэтому старые подписи не подходят
            2.  Подпись сходится только с ключом из ТОЙ ЖЕ пары. Любой другой ключ даст подпись которая попарно не сойдется

    3.  Подход TOFU(trust on first use) - подход при котором, если посетить сайт, публичный ключ сервера запишется и при повторной попытке поделючится, ssh не будет спрашивать, “Это тот сервер к которому вы хотите подключится?”
