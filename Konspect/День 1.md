1.  <span style="--tn-color:#e64d4d;color:#e64d4d;">Права доступа к файлам</span>

*   `ls -l` показывает: тип и права (`-rwxr-xr--`), владельца (user), группу (group), размер, дату, имя.
*   Девять символов прав это три тройки по `rwx`: **владелец**, **группа**, **остальные**.
*   `r` читать, `w` изменять, `x` запускать (для файла).
*   Система выбирает **первую подходящую категорию** в порядке владелец → группа → остальные и применяет только её права. Права следующих категорий не складываются и не подстраховывают.
*   Пример: владелец `anna` в группе `ops`, права `r--rw----`. Для `anna` сработает тройка владельца, поэтому писать она не может, хотя у группы запись есть.
*   Суперпользователя в Linux зовут `root`. Группа это набор пользователей, а не особый пользователь.

Права доступа может менять владелец файла и root:

команды для смены прав доступа:

1.  chmod u+w file(ваш файл)
2.  chmod g-r file(ваш файл)

Категории: u - user, владелец, g - группа, о - остальные.

2.  <span style="--tn-color:#e64d4d;color:#e64d4d;">Сигнали и терминал</span>
    1.  Процессов отдает сигнал SIGHUP на завершение работы для программы
    2.  nohup запускает программу так, чтобы она игнорировала сигнал SIGHUP, и работала после закрытия терминала
3.  <span style="--tn-color:#e64d4d;color:#e64d4d;">Сервер</span> 
    1.  Команда nohup python3 servar.py &
        1.  nohup выше, поэтому надо разобраться с &, этот знак в конце запускает сервер как бы на заднем плане, позволяя писать команды относящиесе к вам, а не серверу в этом же терминале. Если запускать сервер без нее, то консоль будет открыта для ввода на сервер, то есть сервер откроется какбы на переднем плане.
        2.  Если нет nohup, но есть &, сервер закроется, потому что у него не было инструкции nohup, на игнорирование сигнала о выключении.
4.  <span style="--tn-color:#e64d4d;color:#e64d4d;">Процессы тренировка</span>
    1.  Для того чтобы найти процесс по имени используется команда:
        
        pgrep  -a sleep(Заглушка создана sleep 100 &)
    2.  kill PID - не сам убивает процесс, а отправляет ему сигнал на завершение(SIGTERM), но процесс также может его перехватить и игнорировать, как с nohup.
        1.  Для того чтобы процесс не игнорировал kill, у него есть ‘модификатор’ SIGKILL, который указывается в команде, как - 9, kill -9 PID, эту команду обрабатыывает ядро, оно не дает возможности процессу отвечать и у него нет варианта пропустить команду kill.
        2.  Всегда лучше начинать с kill, потому что с SIGKILL, процесс не успевает сохранить все файлы и удалить временные файлы и использовать его только если процесс завис.
5.  <span style="--tn-color:#e64d4d;color:#e64d4d;">Алгоритмы</span>
    1.  Коллизия - это ситуация в хэш таблице, в которой 2 ключа, попадают в одну ячейку.
        
        Перезапись ключа - если 2 ключа одинаковые, то в хэш таблице записывается последний элемент.
        
        **Задача (LeetCode 1, Two Sum, Easy):** дан массив чисел `nums` и число `target`. Нужно найти **индексы** двух разных элементов, сумма которых равна `target`. Решение гарантированно одно, использовать один и тот же элемент дважды нельзя.
        
        Пример: `nums = [2, 7, 11, 15]`, `target = 9` → ответ `[0, 1]`, потому что `2 + 7 = 9`.
