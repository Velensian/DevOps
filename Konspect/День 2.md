Демон - основная программа выполнябщаяся без терминала, работабщая постоянно и ждущая запросов: веб-сервер, база данных, sshd

1.  <span style="--tn-color:#e64d4d;color:#e64d4d;">Unit - файл:</span>
    1.  Файл описывающий, что нужно делать с процессом, для PID 1, который и запускает все остальные службы.
        
        <figure class="image image_resized" style="width:75.51%;"><img style="aspect-ratio:1399/801;" src="api/attachments/3bmgsXRgwRrE/image/%D0%A1%D0%BD%D0%B8%D0%BC%D0%BE%D0%BA%20%D1%8D%D0%BA%D1%80%D0%B0%D0%BD%D0%B0%20%D0%BE%D1%82%202026-11-19%2011-40-41.png" width="1399" height="801"></figure>
    2.  Передаваемые параметры
        1.  для того чтобы выставить параметр запускать после поднятия сети, надо в After = network.target
        2.  Для запуска при обычном запуске системы в WantedBy = milti-user.target
        3.  Для того чтобы у программы не было много прав, больше чем ей надо, ей в user выдается пользователь с ограниченными правами
        4.  ExecStart - место откуда запускается файл(путь к папке), через абсолютный путь(от начала файловой системы до папки), но и с помощью чего запускается, тоже указывается полный путь.
            
            Например ExecStart=/usr/bin/python3 /home/sergey/app/server.py
            
            <span style="--tn-background:#e64d4d;background-color:#e64d4d;">Для ТОГО чтобы НАЙТИ место положение файла</span>, можно написать find ~ -name “имя\_файла”
    3.  Для остановки службы используем команду systemctl stop имя.  
        При ручной остановке процесса, Restart из init файла не перезапускает процесс, даже при инструкции перезапускать всегда.
    4.  WantedBy=multi-user.target
        1.  **target** («цель») в `systemd` это состояние или этап загрузки системы. `multi-user.target` означает «система загружена в обычном режиме: сеть работает, можно запускать службы, графики не обязательно».
        2.  `WantedBy=multi-user.target` значит «эту службу нужно запускать, когда система доходит до этого этапа». Именно строка в секции `[Install]` отвечает за запуск при обычной загрузке.
        3.  Эта связь создаётся не при сохранении файла, а командой `systemctl enable`.
    5.  Для того чтобы посмотреть работает ли прпоцесс надо через  
        systemctl status имя\_процесса(или PID. Он покажет, к какой службе принадлежит этот процесс, и её состояние. Если процесс не относится ни к одной службе (как твой `bash` в терминале), `systemd` отнесёт его к сессии пользователя.)  
         
        
        Для состояния конкретного процесса независимо от `systemd` есть `ps -p <PID> -o pid,stat,cmd`. В колонке `S` / `STAT` видно состояние: `R` работает, `S` ждёт события, `T` остановлен, `Z` зомби.
